# Troubleshooting database

A professional baker does not say "it didn't work". They say *what* is wrong, measure it,
list the causes that could produce exactly that symptom, run the cheapest test that tells
the causes apart, fix it, and write it down. This database is organized that way.

Every entry follows the same structure:

**Symptom → likely causes → how to test → corrective action**

The full method, with worked cases, is taught in
[18.3 The diagnostic method](stage-1/module-18/lesson-03.md). Diagnosis clinics appear
earlier in [05.4](stage-1/module-05/lesson-04.md) (bread), [10.4](stage-1/module-10/lesson-04.md)
(cakes), [14.2](stage-1/module-14/lesson-02.md) (choux) and [15.4](stage-1/module-15/lesson-04.md)
(laminated doughs).

## How to use it

1. **Describe the symptom precisely.** "Dense" is not enough: dense everywhere or only at
   the bottom? Tight small cells or a gummy band? Measure (height, weight, diameter,
   internal temperature) and photograph the cross-section next to a ruler.
2. **Find the entry** by filtering the symptom index below.
3. **Check your [lab notebook](templates/lab-notebook.md)** against each likely cause —
   dough temperature, fermentation times, oven thermometer reading, ingredient changes. Most
   causes can be ruled in or out from records alone, which is why you keep them.
4. **Run the test** in the entry's "How to test" column. Change one variable against a
   control.
5. **Correct, verify, document.** A fix is not a fix until the next batch confirms it.

<div class="callout key">

**Symptoms have several causes, and causes have several symptoms.** A flat loaf can be
over-proofed, under-developed, too slack or baked too cool. That is why each entry lists
several causes with a *test* that separates them, rather than a single answer.

</div>
